Why this thesis exists

Problem

Vision-Language Models are compute-hungry and draw significant power, so IoT developers running them on the edge need to know their workload’s draw to size the right battery, and the existing literature had no framework to comprehensively capture that power in a way that could be analyzed efficiently.

→

Solution

I built a profiling framework from scratch, targeting the Raspberry Pi 5 running Ollama for the implementation, but designed to generalize to any model, inference engine, and device.

02

Three power meters, combined

No single existing method covered subsystem-level detail, measurement accuracy, a custom sampling rate, and cost all at once, so the framework combines three.

IoT-based power meter

~$20 USD

Total device power draw, with a WebSocket interface for real-time measurement.

Software-defined power meter

Free · built into the Pi 5

CPU, RAM, and subsystem power via vcgencmd, at a custom sampling rate.

Plug-based power meter

Verification

An onboard-display meter used to confirm the IoT meter isn’t faulty.
